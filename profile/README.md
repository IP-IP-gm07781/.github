<p>本文讲一条专线接多个住宅IP的完整落地过程，先理清专线与地址的绑定关系，再列设备与账号准备、IP池分层、出口调度、健康检查和故障排查顺序，最后用问答补充细节，方便按步骤对照执行。</p>
<h2>一、先弄清专线和住宅IP的绑定关系</h2>
<p>专线提供的是一条固定上行链路，住宅IP是这条链路上可以使用的地址资源。运营商把一段地址静态路由到你的接入设备，设备再把地址分给下游主机，这是最常见的绑定方式。</p>
<p>很多新手以为插上网线就能拿到多个住宅IP，实际上地址必须先在你的账号名下开通，再逐条指向设备端口。没有做这一步，线路再宽也只有一个地址可用。</p>
<p>判断是否绑定成功，看接入设备的外网口能不能同时持有多个地址，而不是看测速结果。地址列表里出现多条记录，才说明这一段地址真的落到了你这边。</p>
<h2>二、设备与账号准备</h2>
<p>接入侧需要一台能做多地址配置的路由器或软路由，交换机和网线按终端数量准备。软路由的好处是地址与策略都在系统里改，不用反复动硬件。</p>
<p>账号侧要确认三件事：地址段是否已经备案到你的主体、地址是静态还是动态、运营商是否限制同时在线的主机数。这三项在开通单上都能查到，别靠猜。</p>
<h2>三、IP池的分层结构</h2>
<p>把池子拆成三层更好维护：地址层管归属，出口层管转发，调度层管分配。三层分开以后，某个地址掉线不会影响整体，替换也只动一层。</p>
<p>地址层记录每个住宅IP的归属地、运营商、开通日期和当前状态。出口层负责把流量发到指定地址。调度层按业务需求挑一个可用地址交给上游。</p>
<h3>三层之间用什么连接</h3>
<p>地址层和出口层之间用路由表连接，出口层和调度层之间用接口或代理端口连接。用端口对接的好处是上层不需要知道底层是几条线路。</p>

<h2>四、出口调度与代理端口</h2>
<p>住宅IP通常通过代理端口对外提供，每个端口固定对应一个地址。端口号与地址做一对一映射，上游业务只改端口就能换地址，不用改代码。</p>
<h3>端口映射的写法</h3>
<p>映射表建议直接写成配置文件，格式为端口、地址、备注三段。改配置后重启服务即可生效，纸上记录容易和实际不一致。</p>
<p>调度层要设置失败计数，某个端口连续失败就临时摘掉，过一段时间再放回。没有这一步，一个坏地址会拖慢整批任务。</p>
<h2>五、稳定性与健康检查</h2>
<p>健康检查分两种：一种是探地址本身通不通，一种是探目标站点能不能访问。前者能发现线路中断，后者能发现地址被目标侧限制，两者都要做。</p>
<h3>记录哪些指标</h3>
<p>至少记录延迟、丢包、连续失败次数和最近一次成功时间。四个数字放在一张表里，哪条地址该换一眼就能看出来，不用逐条登录去试。</p>

<h2>六、故障排查顺序</h2>
<p>排查按从下往上走：先看物理链路灯，再看设备是否持有地址，再看端口能否连通，最后看业务侧配置。跳步排查最费时间，因为问题往往在更下面一层。</p>
<p>如果只有一个地址不通，先换端口再换设备，多数情况是地址侧的问题。如果整段都不通，先看运营商侧状态，别在本地反复重装。</p>
<h2>常见问答</h2>
<h3>一条专线最多能带多少个住宅IP？</h3>
<p>答：数量取决于运营商分配给你的地址段和设备的转发能力，常见是四个到十六个一段，扩容需要单独申请。</p>
<h3>多个住宅IP可以共用一个路由器吗？</h3>
<p>答：可以。只要路由器支持多地址配置，并为每个地址建立独立的出口策略，就能在一台设备上跑多个住宅IP。</p>
<h3>IP池里某个地址掉线会影响其他地址吗？</h3>
<p>答：通常不会。地址之间是独立路由，调度层发现失败后摘掉该地址即可，其他地址继续工作。</p>
<h3>搭建IP池需要备案吗？</h3>
<p>答：取决于所在地区的管理规定和运营商要求，开通前应向服务商确认地址用途与备案义务，避免后期被停用。</p>
